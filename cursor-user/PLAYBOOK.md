# Cursor AI Playbook (for daily use)

Короткая памятка, чтобы работа шла как с напарником, а не с автопилотом.

## 1) Быстрый старт на каждую задачу

1. Начни с `/analyze` (понять контекст, план, риски).
2. Зафиксируй один маленький шаг (одно логическое изменение).
3. Сделай проверку, только потом следующий шаг.

Правило: не проси "сделай все сразу", проси "сделай шаг 1 из плана".

## 2) Что использовать: commands vs skills vs subagents

- Commands (`/analyze`, `/review-smells`, `/incident`, `/deploy-plan`, `/runbook`, `/rca`)
  - Используй как быстрые шаблоны запроса.
  - Лучший выбор для старта любой задачи.
- Skills (`root-cause-debug`, `safe-refactor-small-steps`, `devops-incident-triage`, `safe-deploy-checklist`)
  - Используй для более "режимной" работы с фиксированным процессом.
  - Подходят, когда нужен контроль качества и повторяемость шагов.
- Subagents (`codebase-explorer`, `release-safety-auditor`)
  - Используй для отдельной аналитической подзадачи.
  - Не для рутины; подключай, когда нужен сфокусированный обзор.

## 3) Ежедневный рабочий цикл

### Новый/незнакомый проект

1. `/analyze`
2. `codebase-explorer`
3. `safe-refactor-small-steps` на первый diff
4. Проверки и только потом следующий шаг

### Баг/регрессия

1. `/incident`
2. `root-cause-debug`
3. Минимальный фикс
4. `/rca` после стабилизации

### Релиз/деплой

1. `/deploy-plan`
2. `safe-deploy-checklist`
3. `release-safety-auditor`
4. `/runbook` (обновить или создать)

## 4) Готовые фразы (копируй как есть)

- "Сначала только анализ без правок: где root cause и как воспроизвести?"
- "Дай план из 3 маленьких шагов, начни с шага 1."
- "Покажи минимальный diff только для этого шага."
- "Какие проверки после этого шага? Команды + ожидаемый результат."
- "Какие риски и rollback, если шаг не сработает?"

## 5) Антипаттерны (не делать)

- "Сгенерируй весь конфиг целиком."
- "Почини быстро, детали не важны."
- Делать 5+ изменений за один проход без промежуточной проверки.
- Пропускать проверку после каждого шага.

## 6) Мини-чеклист перед завершением задачи

- Есть ли подтвержденная первопричина?
- Изменения минимальные и понятные?
- Проверки пройдены?
- Риски и rollback понятны?
- Нужен ли `/runbook` или `/rca` по итогам?

## 7) Git policy (твой режим)

- AI по умолчанию не делает commit/push.
- AI готовит diff, команды и commit message.
- Commit и push выполняешь вручную.
