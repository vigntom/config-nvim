# Cursor CLI / workflow — журнал проблем и неудобств

Здесь фиксируем, с чем сталкиваемся при настройке **cursor-cli** и связанного workflow (nvim, терминал, скрипты). Цель — не терять контекст и со временем приоритизировать фиксы.

## Как писать

1. Добавляй записи **в конец** раздела «Журнал» (или группируй по датам блоками).
2. Одна запись = один смысловой кейс (можно несколько связанных пунктов внутри).
3. По желанию: **серьёзность** — `blocker` / `annoying` / `nit`.
4. Если нашёл обходной путь — отдельным подпунктом **Workaround**.

### Шаблон записи

Скопируй блок и заполни:

```markdown
### YYYY-MM-DD — короткий заголовок

- **Контекст:** (что делал, какая команда/режим)
- **Симптом:** (что пошло не так)
- **Ожидание:** (как должно быть)
- **Серьёзность:** annoying
- **Workaround:** (если есть; иначе «—»)
- **Ссылки:** (issue, коммит, путь к файлу в конфиге — по желанию)
```

### 2026-04-05 — В чате агента Cursor не выделяются свои промпты

- **Контекст:** Панель Agent в Cursor; длинные треды, нужно быстро отличать «мой вопрос» от ответа модели.
- **Симптом:** Сообщения пользователя визуально почти не отличаются от ответов ассистента — сканировать тред неудобно. Отдельной настройки подсветки «только мои реплики» в продукте по сути нет (идеи есть на forum.cursor.com).
- **Ожидание:** Хотя бы фон/акцент/роль в разметке, чтобы глаз цеплялся за свои промпты.
- **Серьёзность:** annoying
- **Workaround:** — (копировать важное во внешние заметки; дробить сессии). Встроенного «как в IDE хочется» нет.
- **Идея на потом (совместно):** Уже есть заход через Neovim: чаты лежат под `~/.cursor/chats/<ws>/<id>/store.db`, см. `lua/cursor_chats.lua` (sqlite3 + meta). Имеет смысл когда будет время посмотреть **как в БД лежат сообщения** (таблицы/поля роли user vs assistant) — возможно получится свой обходной просмотр или подсветка (скрипт, nvim-буфер, экспорт), не дожидаясь фичи в UI.
- **Ссылки:** `~/.config/nvim/lua/cursor_chats.lua`, `lua/plugins/cursor_cli.lua` (cursoragent.nvim).

### 2026-04-05 — Русская раскладка vs латинские хоткеи (Vim и чат с ИИ)

- **Контекст:** Пишешь по-русски (вставка текста, промпты агенту). В Neovim вне **режима вставки** (Normal / Visual / командная строка `:`) буквенные клавиши — это команды, и они **задуманы под латиницу** (hjkl, yyp, `:w` и т.д.). В Cursor то же самое касается **поля чата с ИИ** и шорткатов редактора: часть ожидает латиницу.
- **Симптом:** Постоянно переключать раскладку RU ↔ EN: иначе в Normal вместо команды получается «кракозябра» или ничего; в чате/хоткеях — промах по shortcut.
- **Ожидание:** Меньше трения: либо единая привычка «в командном контексте всегда EN», либо автопереключение раскладки по режиму/фокусу, либо дублирующие русские бинды (спорно и не везде возможно).
- **Серьёзность:** annoying
- **Workaround:** Ручное переключение перед Normal/после Insert; у части людей — отдельный переключатель раскладки только для «командного» слоя (XKB, ibus, плагины вроде переключения при `InsertLeave` — обсуждаемо отдельно).
- **Идея на потом:** Пройтись по своему стеку (ОС, IME, Neovim `iminsert`/`langmap` если уместно, настройки Cursor) и зафиксировать **один** рабочий паттерн, чтобы не дергать раскладку на автомате десять раз в минуту.

### 2026-04-14 — Визуальное различие user/agent: терминальный `cursor-agent` vs nvim-плагин

- **Контекст:** Сравнение UX между запуском `cursor-agent` в обычном терминале и работой через `cursoragent.nvim`.
- **Симптом:** В terminal UI `cursor-agent` сообщения пользователя визуально отличаются от ответов агента, а в окне плагина в Neovim различие слабее/менее очевидно.
- **Ожидание:** Одинаково читаемая дифференциация ролей (user/assistant) и в плагине.
- **Серьёзность:** annoying
- **Workaround:** Когда нужен более читаемый поток диалога — запускать `cursor-agent` напрямую в терминале.
- **Ссылки:** `lua/plugins/cursor_cli.lua`, `lua/cursor_chats.lua`.
